## 0. 拓扑结论（已核实，无需改 nginx）

- 前端 nginx `proxy_pass http://backend:8080`（`frontend-v2/nginx.conf:12`）走 Docker 内部
  DNS + `resolver 127.0.0.11 valid=30s`——backend 服务起两个容器后，**每请求自动轮询两实例**。
- SSE（`/api/events/stream`）连接会钉在其中一个实例；后续 REST 写可能落到另一实例
  → 这正是 W2 广播要覆盖的场景（冒烟已证跨实例投递）。
- clawsynapse webhook `http://backend:8080/...` 同样轮询——**双实例下事件落到非 SSE 持有实例
  的概率约 50%**，所以 `SSE_BROADCAST_ENABLED` 必须与第二实例**同批**开启，不能只加实例。
- JWT_SECRET 两实例同源（`.env`），token 跨实例有效。限流器是进程内的，双实例≈2 倍配额，可接受。

## 4. 已知风险与不阻塞声明

- **NATS 共享生产**：本方案不新增任何 NATS 连接（甲方拍板），webhook 拓扑不变。
- **Mongo 压力**：tailer 每实例 500ms 一次小查询 + 每事件 2 次写（$inc+insert）；当前事件量级
  （办公室页）远低于阈值，TTL 60s 保证集合有界。
- **seq 空洞**：writer 分配 seq 后崩溃 → tailer 等 3 轮（1.5s）跳过，只延迟不丢失。
- **读侧陈旧 ≤10s**（W3 未做，甲方已接受）：前端轮询兜底覆盖。
- 两实例同时滚动重启的窗口内事件仅本地投递（outbox 停写），恢复后不补发——与关闭态行为一致，可接受。

### 踩坑记录（务必沿用）
**Windows 上 `git archive | tar` 会破坏二进制流**：PowerShell 文本管道逐行重组时改写行尾，
导致 `docker-entrypoint.sh` 变成 CRLF → 容器 `exec: no such file or directory` 重启循环。
且 `git archive` 本身遵循 `core.autocrlf=true` 做换行转换。
**正确姿势**（已验证）：
```powershell
git -c core.autocrlf=false -c core.eol=lf archive --format=tar -o _export.tar HEAD:backend
tar -xf _export.tar -C _build_backend
```
首次部署因此失败并**已完整回滚**（healthz 200 后重建），第二次成功。
