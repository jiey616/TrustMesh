> 状态：**规格已就绪，待批准后实施**（架构级改动，遵循本项目「先方案后动手」）。
> 依据：`docs/optimization-plan-2026-09-11.md` §2.4 T2.2；依赖 T2.1（已完成）。

## 1. 目标

把任务域（Task/Todo）的写路径从「**内存权威 + 集中式尽力镜像（`persistTaskBundleUnsafe`）**」改为「**Mongo 权威（write-through，版本号/乐观锁）**」：

- `persistTaskBundleUnsafe` 升级为**权威提交原语**——先做版本化 Mongo 写并确认，再（由调用方）落实内存；失败则**不产生内存副作用**。
- 引入乐观锁，消灭「并发写互相覆盖（last-writer-wins 全量 ReplaceOne）」的丢失更新。
- 兑现「重启零丢失且流水线可继续推进」。

## 2. 现状（代码事实）

任务域与会议域架构不同：**任务域没有逐路径的 Mongo I/O**，而是所有写路径先在内存改 `s.tasks[taskID]`，再统一调用集中式 `persistTaskBundleUnsafe`：

| 事实 | 位置 | 问题 |
|------|------|------|
| `persistTaskUnsafe` 用 `ReplaceOne(ctx, {_id}, copyTask(task), Upsert(true))` | `mongo_state.go:850-858` | **无 version filter** → 并发写互相覆盖（全量替换，last-writer-wins） |
| `persistTaskBundleUnsafe` = `persistTaskUnsafe` + `persistTaskEventsUnsafe` | `mongo_state.go:947-956` | 包成 bundle，但底层仍无锁 |
| `model.TaskDetail.Version int` 已存在 | `model/task.go:290`（`bson:"version"`，无 omitempty） | **未被用作锁**，目前只是冗余字段 |
| 调用方「先改内存、后 persist」，且大量调用点**吞错** | `store_task.go:220`（仅 `s.log.Warn`）、`store_artifact.go:403/695`、`mongo_state.go:939` | Mongo 故障 = 内存领先且日志只 warn；与会议域 T2.1 前的 bug 同类 |
| 调用点数量 | `workflow.go` ~20 处、`store_planning.go` 6 处、`store_artifact.go` 2 处、`store_project.go` 1 处、`mongo_state.go` 批量 1 处 | 覆盖面远大于会议域 6 路径 |

结论：任务域**已经是「每写必镜像」**，所以 Mongo 与内存通常一致；真正的两类缺口与会议域 T2.1 同源——
1. **无乐观锁**：并发写互相覆盖（最严重，单函数可修）；
2. **零副作用未保证**：persist 失败（冲突/网络）时内存已改且部分调用点吞错 → 进程重启即丢该笔变更。

## 3. 改造设计

### 3.1 版本化权威提交原语（核心，单函数改动覆盖面最大）

在 `mongo_state.go` 新增 `applyTaskVersionedReplaceLocked(task *model.TaskDetail) *transport.AppError`（对齐 `meeting.go:75` 的 `applyMeetingVersionedUpdateLocked`）：

```
cur := task.Version
next := cur + 1
doc := copyTask(task)
doc.Version = next
res, err := s.mongoTasks.ReplaceOne(ctx, bson.M{"_id": task.ID, "version": cur}, doc, options.Replace().SetUpsert(true))
if err != nil → return mongoWriteError(err)
if res.ModifiedCount > 0 || res.UpsertedCount > 0 → task.Version = next; return nil
// 未命中：先试存量自愈（P1），否则 409
if appErr := s.healZeroVersionTaskLocked(task, cur); appErr != nil → return appErr
task.Version = next
return nil
```

- **新任务**：创建时 `Version` 置 1（`workflow.go:366/535`），doc 不存在 → filter `{_id, version:1}` 不匹配 → upsert 建文档（`UpsertedCount>0`）→ 成功，内存推进到 2。与会议域语义一致。
- **Mongo 未启用（纯内存模式）**：不写 Mongo，仅 `task.Version = next` 保持内存自洽（对齐 meeting 的降级分支）。
- `persistTaskBundleUnsafe` 改为：先 `applyTaskVersionedReplaceLocked(task)`；失败→返回错误（由调用方回滚）；成功→再 `persistTaskEventsUnsafe`（事件为派生、可重同步，失败仅 `s.log.Warn` 不阻断提交）。

### 3.2 存量 version≤0 自愈（P1，对齐 T2.1）

- 启动 `loadMongoState` 在 `loadTasks` 前调用 `backfillTaskVersions`：filter `bson.M{"version": bson.M{"$not": bson.M{"$gt": 0}}}`（覆盖显式 0 / null / 负），一次性 `UpdateMany` 置 1。
- 滚动发布窗口（旧镜像新建的文档）由 `healZeroVersionTaskLocked`（对齐 `meeting.go:124`）在冲突时一次性修库内 version 后重试；`doc.Version > 0` 仍冲突才如实 409。

### 3.3 零副作用提交包装器（关键写路径）

新增 `mutateTaskUnsafe(taskID string, fn func(*model.TaskDetail) *transport.AppError) *transport.AppError`（store.go）：

```
snapshot := copyTask(s.tasks[taskID])   // 深拷贝快照（copyTask 已拷贝切片/指针；Version 随结构体拷贝保留）
appErr := fn(s.tasks[taskID])           // fn 就地改内存
if appErr != nil → s.tasks[taskID] = snapshot; return appErr
if pErr := s.persistTaskBundleUnsafe(taskID); pErr != nil → s.tasks[taskID] = snapshot; return pErr
return nil
```

**把核心 Task/Todo 写路径改造为「先 fn 改内存、再 persist、失败回滚快照」**。改造时删除调用点内部多余的 `task, ok := s.tasks[taskID]` 取值（由包装器提供 `task`）。

### 3.4 双写过渡与校验（对齐 T2.1 §3.4）

- 新增只读 `VerifyTaskConsistency() (checked, mismatched int, err error)`（对齐 `VerifyMeetingConsistency`）：遍历内存任务，逐条与 Mongo 文档比对关键字段（Status / Todos 数 / Version / UpdatedAt），返回 `mismatched`。
- 双写过渡期断言 `mismatched == 0`；接入既有 `org_verify` 式校验入口。

## 5. 验收标准

1. **Mongo 失败零副作用**（核心路径）：注入 persist 失败 → 接口返错，且 `s.tasks[taskID]` **未**被修改（本批最重要的一条）。
2. **乐观锁**：并发两次更新同一任务 → 第二次返回 `TASK_VERSION_CONFLICT`（409）而非静默覆盖。
3. **重启零丢失 + 流水线可续推**：写入后模拟重启（rehydrate）→ 任务、Todo、评论、会话态全部可读回且流水线从断点继续。
4. **校验**：双写过渡期 `VerifyTaskConsistency` 的 `mismatched == 0`。
5. `go build ./...` + `go test ./...` + `go test -race ./internal/store/...` 全绿；既有 `workflow_test.go` / `store_org_test.go` 不回归。
6. 遗留 version≤0 存量文档被 backfill 修复，不再永久锁死。

## 6. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 持锁内做 Mongo I/O 拉长临界区 | 本批先接受（同 T2.1）；T2.5 再拆细粒度锁；监控 `MONGO_TIMEOUT=5s` |
| 乐观锁引入新冲突错误面 | 仅真实并发写出现；核心路径通过 `mutateTaskUnsafe` 回滚，调用点上抛 |
| 版本化 ReplaceOne 对「新任务」语义 | upsert + version=1 建文档已验证可行（§3.1） |
| 调用点覆盖面大 | 分簇提交，每簇一测；双写过渡期可切回内存优先 |
| 事件重同步 | 事件 persist 失败仅 warn，任务文档权威，下次写自愈 |

**回滚**：按簇分批 commit，可整批 revert；双写期内内存仍可用。

### 8.4 实施中发现并修复的真实缺陷
1. **Go typed-nil 陷阱（P0）**：`persistTaskUnsafe` 签名是 `error`，却被改成直接 `return s.applyTaskVersionedReplaceLocked(task)`（返回 `*transport.AppError`）。成功时的 nil 指针装进 error 接口后**非 nil** → `persistAgentGraphUnsafe` 把成功当失败上抛 → `mongoWriteError` 再解开成 nil → `CreateTaskByPMNode` 返回 `(nil, nil)`，调用方解引用即 panic（3 个既有测试直接崩溃）。
   修复：显式判空；并加固 `mongoWriteError`（typed-nil → 明确 500，而不是静默 nil）。回归护栏：`TestPersistTaskUnsafeSuccessReturnsNilError` + `TestCreateTaskByPMNodeReturnsTask`。
2. **dup-key 误报 500**：Upsert 的 filter 含 `_id`，文档存在但 version 不匹配时服务端返回 E11000（而非 `ModifiedCount==0`）；必须并入「未命中」分支，否则版本冲突被误报 500、且 heal 分支永远不可达。
3. **Verify 时间戳假 mismatch**：`taskSnapshotMatches` 原比较 `UpdatedAt`（BSON 毫秒 vs Go 纳秒）恒判不等 → 改为不比时间（对齐会议域 `meetingSnapshotMatches`）。
4. **版本推进职责收敛**：`workflow_cancel_notify_test.go` 期望 1 → 2、`resetArchivedProjectTasksUnsafe` 删掉手写 `task.Version++` —— 版本推进统一由提交原语负责，避免双重自增制造假冲突。
