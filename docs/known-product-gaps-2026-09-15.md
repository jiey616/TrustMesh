## G1 代建账号 — 接受为已知缺口

- **症状**：平台/admin 无法代用户创建账号，第二个账号只能走自助 `/register`。
- **代码事实**：路由中只有 `/users/me`（PATCH）与 `/users/me/password`（POST），**没有任何 admin 建号端点**。
- **决策**：接受。等真有客户需要「平台代开成员账号」时再立项，届时**与 G2 邀请一并设计**（两者同属「企业成员供给」这一件事）。
- **复评触发**：出现第二个真实企业租户且需要平台代建成员。

## G2 邀请链接 — 接受为已知缺口

- **症状**：只能「按邮箱加已注册成员」，没有邀请码 / 邀请链接，拉人入企体验断裂。
- **代码事实**：成员管理只有 `POST /organizations/:id/members`（AddMember，按邮箱加**已注册**用户）；`/agents/invite-prompt` 是 **agent 节点**入企用的，与成员邀请无关。
- **决策**：接受。沟通成本由运维 / 文档承担，代码不动。
- **复评触发**：同上（与 G1 一并重评）。

## G4 配额强制 — 接受为已知缺口

- **症状**：配额接口返回但**全 -1**，无任何强制。
- **代码事实**：`model.OrgQuota` 字段齐全（`MaxMembers` / `MaxNodes` / `MaxProjects` / `MaxStorageBytes`，`-1 = 不限`），但 `DefaultOrgQuota()` 全返回 `-1`，注释写明「只留字段与上限校验，不做计费（分支 F）」「二期接计费后再收紧」。即**有字段、零强制**。
- **决策**：接受。当前单租户无滥用风险；计划书把它排在**阶段 4 的 T4.1（货币化护栏）**，届时再从占位改为 scope 层上限校验。
- **复评触发**：商业化 / 计费立项，或出现资源滥用迹象。

## G7 新租户无 PM agent — 接受为已知缺口

新企业租户开通后 `POST /projects` 报 `PROJECT_PM_AGENT_INVALID`。不在生产常驻 PM agent、不放宽 `pm_agent_id` 必填；由运维按 T1.7 验证过的闭环代配。
完整决策、变通步骤与复评触发条件见 **`docs/p1-g7-known-gap-decision-2026-09-15.md`**。

## T1.6 协议 schema 门禁 — 保留机制，显著标注「生产禁止翻转」

- **结论**：门禁**保留**（机制 + 计数 + 一行回退都在，成本为零），但在代码与文档中显著标注**生产禁止翻转**。
- **为什么不能翻**：`requiresProtocolEnvelope` 覆盖的 11 类消息，其生产者（`skills/tm-task-plan`、`tm-task-exec`）实测**全部仍输出裸 JSON** —— 全仓唯一构造 `{"protocol":...}` 的地方只有测试文件。一旦 `TRUSTMESH_STRICT_PROTOCOL_SCHEMA_GATE=true`，这 11 类 task/todo 消息会被**整体 422**，爆炸半径与 2026-09-02 transfer 事故同级且更广。（`transfer.received` 已作为同类问题从表中移除，见 QA 复验。）
- **翻转前置条件（缺一不可）**：
  1. 迁移 `tm-task-plan` / `tm-task-exec` 生产者技能改用协议信封 —— 注意**本地技能 ≠ 容器 / hermes-data 卷里 agent 实际加载的版本**，必须按运行时逐一证伪；
  2. 按 type 归因（warn 日志带 type 字段）确认 `protocol_schema_warned_total` 归零。
- **已做**：`backend/internal/clawsynapse/webhook.go` 在 `strictProtocolSchemaGate` 声明处加了 🚨🚨 警示块（含上述前置条件）。**纯注释改动**，随下次部署生效，不单独为它重启生产。
- **现有护栏**：`TestStrictProtocolGateDoesNotBlockTransferReceived`、`TestStrictProtocolGateDoesNotBlockMalformedTaskReply` 两个端到端回归测试锁住「不误伤」。

## 复评触发（整体）

满足任一即整体重评 G1 / G2 / G4 / G7：

1. 出现**第二个及以上真实企业租户**需要自助开通；
2. 「企业自助开通」被列入产品需求；
3. 运维代配 / 人工沟通在真实开租户时**实际成为阻塞**；
4. 商业化 / 计费立项（直接触发 G4）。
