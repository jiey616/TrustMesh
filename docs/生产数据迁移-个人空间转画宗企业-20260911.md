## 二、切换的必要性：为什么不能只改一个字段

### 2.1 裁决规则（`store/scope.go:44` `visibleToScope`）

```go
if sc.HasOrg() && ownerOrgID != "" {
    return ownedByOrg(sc, ownerOrgID)     // 有租户头 + 资源已回填 → 按 org 裁决
}
return ownedByUser(sc, ownerUserID)       // 否则退回 user 维度
```

用户在前端切到画宗后，所有请求带 `X-Org-Id: org_d15fa58a…`，此时：
- 资源 `org_id = org_d15fa58a…` → ✅ 可见
- 资源 `org_id = org_6a9ad805…`（个人）→ ❌ **不可见**

### 2.2 实测证据（切换前）

| 接口 | 无头（个人空间） | 带画宗头 |
|---|---|---|
| `GET /projects` | 200，**5 条** | 200，**0 条** |
| `GET /agents` | 200，**6 条** | 200，**0 条** |
| `GET /organizations` | 200，2 条 | 200，2 条（不受头影响） |

→ **仅在前端切租户不够**，必须把数据的 `org_id` 从个人租户改到画宗。

### 2.3 好消息：events 会自动跟随

`store/store_events.go:68` `reindexEventOrgsUnsafe()` 在**每次 backend 启动时**执行（`mongo_state.go:400`），
按 `任务 → 项目 → 执行 agent → 个人租户兜底` 重算每条事件的租户归属：

```go
func (s *Store) resolveEventOrgUnsafe(taskID, projectID, actorType, actorID, userID string) string
```

→ 只要 projects / tasks / agents 的 `org_id` 改到画宗，events **重启后自动校正**，
包括那 12 条无字段的（走 project_id 分支 → 画宗）。

### 2.4 不需要动的

| 集合 | 原因 |
|---|---|
| `users` | user 维度资源，不参与租户裁决（`router.go:331` 明确注释） |
| `organizations` / `org_memberships` | 租户定义与成员关系本身 —— test001 已是画宗 owner，**无需新增** |
| `platform_settings` | 全局配置（含 API key），非租户资源 |
| `org_c7fd3977…`「测试02」 | 孤儿组织，不属本次范围 |

## 三、方案

### 方案 A（推荐）：Mongo 层定点回填 `org_id`

**核心**：停 backend → 改 Mongo 15 个集合的 `org_id` → 重启 backend（触发 events 自动重算）。

**改动清单**（`personal → huazong`）：

| # | 集合 | 改动条数 | 备注 |
|---|---|---:|---|
| 1 | projects | 5 | |
| 2 | tasks | 38 | |
| 3 | agents | 7 | |
| 4 | project_files | 125 | |
| 5 | artifacts | 158 | |
| 6 | comments | 1049 | |
| 7 | notifications | 1164 | |
| 8 | agent_chats | 27 | |
| 9 | meetings | 1 | |
| 10 | meeting_messages | 5 | |
| 11 | knowledge_documents | 1 | |
| 12 | knowledge_chunks | 11 | |
| 13 | join_requests | 8 | 见 §4 决策点 |
| 14 | workflow_templates | 1 | |
| 15 | events | 2019 | **可跳过**，重启自动重算（保留作兜底更省事） |
| | **合计** | **2601** | （不含 events 则 582） |

**执行步骤**：

```
阶段 0  备份（可回滚）
  0.1 mongodump 全库 → /opt/trustmesh-test/backup-<ts>-orgmove/mongo-dump
  0.2 记录改前计数快照（本文档 §1.2）

阶段 1  停 backend（🔴 必须，Store 全内存状态机会回写覆盖 Mongo）
  1.1 docker stop trustmesh-backend
  1.2 轮询 docker inspect -f '{{.State.Status}}' 到 exited

阶段 2  Mongo 定点回填
  2.1 逐集合 updateMany({org_id:"org_6a9ad805…"}, {$set:{org_id:"org_d15fa58a…"}})
  2.2 events 额外：给 12 条无字段的补 org_id（或交给重启自动算）
  2.3 打印每个集合改后计数核对

阶段 3  重启 + 验证
  3.1 docker start trustmesh-backend（或按部署铁律 rm + up -d）
  3.2 轮询 healthy，再等 6~8s
  3.3 重新登录拿 token（🔴 重启后旧 JWT 失效）
  3.4 带画宗头回归：/projects 应 5 条、/agents 应 6 条
  3.5 抽查：项目详情 / 流程进度 / 文件树 / 会议 / 通知
  3.6 确认个人空间视角已空（/projects 无头 → 0 条，符合预期）
```

**优点**：靶向精确、0 删除、可逐集合核对、events 自动跟随、改动量可控。
**风险**：低。唯一硬约束是「必须先停 backend」。

---

### 方案 B：走 API 逐个资源 PATCH

调 `PATCH /projects/:id` 等接口带画宗头逐条改。

**否决**：① 需逐个资源类型写脚本，projects/tasks/agents 有 PATCH，但 artifacts/comments/notifications/events **无对外 PATCH 接口**；② 1200+ 条 notifications 无接口可改；③ 会触发事件风暴。**不可行。**

### 方案 C：写 Go 迁移命令（`cmd/migrate-org`）

在 backend 内加一次性命令，走 Store 内存层 + 持久化。

**否决**：需改代码 + 重建镜像 + 再部署一轮，成本远高于方案 A，收益相同。**本次不采用**（若未来要做通用「组织迁移」功能，可作为产品化方向）。

## 四、需要你决策的 4 个点

| # | 决策点 | 选项 | 推荐 |
|---|---|---|---|
| **D1** | `join_requests` 8 条是否一起迁 | ① 一起迁（保持整片一致）② 不迁（它们是「加入个人空间」的历史申请，语义上属于个人租户） | **①一并迁** —— 否则画宗视图下 `join_requests` 相关 UI 会空，且这 8 条全是 test001 自己的 approved 记录，无敏感语义 |
| **D2** | 个人租户 `org_6a9ad805…` 是否保留 | ① 保留（用户仍可在「个人空间」视图切换，但会是空的）② 删除（彻底只留画宗） | **①保留** —— 删组织需同时清 membership，且用户注册体系依赖个人租户存在；保留空壳零成本、可逆 |
| **D3** | 「测试02」孤儿组织是否顺手清 | ① 本次不动 ② 顺手删 | **①本次不动** —— 与本需求无关，避免混淆变更范围 |
| **D4** | `notifications` 1164 条 | ① 全迁 ② 只迁未读 | **①全迁** —— 历史通知属于这批项目的活动流，割裂会导致时间线断档 |

## 五、风险与对策

| # | 风险 | 对策 |
|---|---|---|
| R1 | 🔴 **Store 内存态回写覆盖** | 改 Mongo 前**必须** stop backend + 轮询 exited（`docker inspect`），改完再 start |
| R2 | events 12 条无字段 | 重启时 `reindexEventOrgsUnsafe` 自动补（走 project_id → 画宗）；可先跑一次验证 |
| R3 | 重启后 JWT 失效 | 验证前重新登录，且等 healthy 后再等 6~8s |
| R4 | 字段名大小写 | 全库实测均为 **snake_case** `org_id`，无 camelCase 变体 |
| R5 | 回滚需求 | 备份在 `/opt/trustmesh-test/backup-<ts>-orgmove/`；回滚 = 停 backend → `mongorestore --drop` → 起 backend |
| R6 | 前端未切租户 | 数据改完后，用户需在前端**切到「画宗」**查看；不带头的「个人空间」视图会变空（设计如此） |
| R7 | 探测必须 `--noproxy '*'` | 本机全局代理 127.0.0.1:62135，不加则全 000 |
| R8 | `film-mcp-*` 2 个容器 | 无关业务，**勿动** |
| R9 | 是否有遗漏集合 | 已全量扫描 16 个含数据的集合（§1.2），无遗漏 |
