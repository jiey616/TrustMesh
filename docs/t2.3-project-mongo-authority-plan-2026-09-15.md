## 1. 目标

把项目域（Project 及其内嵌 Workflows）的写路径从「**内存权威 + 集中式尽力镜像（`persistProjectUnsafe`）**」改为「**Mongo 权威（write-through，Version 乐观锁）**」：

- `persistProjectUnsafe` 升级为**权威提交原语**——先做版本化 Mongo 写并确认，失败则**不产生内存副作用**。
- 引入乐观锁，消灭「并发写互相覆盖（last-writer-wins 全量 `ReplaceOne`）」的丢失更新。
- 兑现「重启零丢失」：项目 / 工作流 / 归档状态全部可读回。
- 复用 T2.1/T2.2 已验证的同构骨架（版本化提交原语 + 存量自愈回填 + 快照回滚包装器 + 只读双写校验），**不发明新机制**。

### 2.3 🔴 改造前已存在的零副作用缺陷（本批必须一并修）

`CreateProject`（`store_project.go:115-118`）：

```go
s.projects[project.ID] = project
if err := s.persistProjectUnsafe(project); err != nil {
    return nil, mongoWriteError(err)   // ⚠️ 只 return，没有 delete(s.projects, project.ID)
}
```

Mongo 写失败时**内存里残留一个 Mongo 没有的「幽灵项目」**：`ListProjects` 能列出它、`GetProject` 能取到它，但进程重启即消失（且其 `TaskSummary` 是重算的、看起来正常）。这与 T2.2 修掉的 `CreateTaskByUser`（那边已 `delete(s.tasks, ...)`）同类，但**这边漏了**。详见 §3.4 修复方式。

## 3. 改造设计

### 3.1 给 `model.Project` 增加 `Version`

```go
// model/project.go
Version int `json:"version" bson:"version"`   // 无 omitempty：必须恒落库
```

- 新增 `const projectVersionFloor = 1`、`projectVersionConflictCode = "PROJECT_VERSION_CONFLICT"`、`isProjectVersionConflict`（对齐 T2.2 的 task 同名常量）。
- **索引**：`mongoProjects` 现有索引（`user_id` / `pm_agent_id`）不动；乐观锁 filter 走 `_id`，无需新索引。

### 3.2 版本化权威提交原语（核心，单函数改动覆盖面最大）

在 `mongo_state.go` 新增 `applyProjectVersionedReplaceLocked(project *model.Project) *transport.AppError`，**逐行对齐** `applyTaskVersionedReplaceLocked`（`mongo_state.go:1048`）：

```
normalizeProjectVersion(project)
cur := project.Version; next := cur + 1
if !mongoEnabled || mongoProjects == nil { project.Version = next; return nil }   // 纯内存模式
doc := copyProject(project); doc.Version = next
res, err := mongoProjects.ReplaceOne(ctx, bson.M{"_id": id, "version": cur}, doc, Upsert(true))
if err != nil && !mongo.IsDuplicateKeyError(err) { return mongoWriteError(err) }  // 🔴 见下
if err == nil && res != nil && (res.ModifiedCount > 0 || res.UpsertedCount > 0) { project.Version = next; return nil }
if appErr := s.healZeroVersionProjectLocked(project, cur); appErr != nil { return appErr }
project.Version = next; return nil
```

**两条硬性要求（承 T2.2 的血泪教训）：**

1. **dup-key 必须并入「未命中」分支**：Upsert 的 filter 含 `_id`，文档已存在但 version 不匹配时服务端返回 **E11000 duplicate key**，而**不是** `ModifiedCount == 0`。若不判 `mongo.IsDuplicateKeyError`，版本冲突会被误报成 500，且 heal 分支**永远不可达**。
2. **`persistProjectUnsafe` 改签名后必须显式判空**：T2.2 中 `persistTaskUnsafe` 声明返回 `error` 却直接 `return s.applyTaskVersionedReplaceLocked(task)` —— 成功时返回的是**nil 指针**，装进 `error` 接口后**非 nil**（Go typed-nil 陷阱），调用方把成功当失败，最终 `CreateTaskByPMNode` 返回 `(nil, nil)` 并导致 3 个测试 panic。
   **本批要求**：`persistProjectUnsafe` **统一改为返回 `*transport.AppError`**（而非 `error`），并在所有调用点把 `mongoWriteError(err)` 的包装去掉（直接返回 appErr）。若保留 `error` 签名则必须 `if appErr := ...; appErr != nil { return appErr }; return nil`。**二者只能选其一，绝不能裸 `return s.applyProjectVersionedReplaceLocked(project)`。**

**`FlushPersistAll` 与 `persistAgentGraphUnsafe` 的版本推进语义**：
- `FlushPersistAll`（全程持 `s.mu`）与 `persistAgentGraphUnsafe` 会**对所有相关项目做一次成功的版本化替换 → 每次刷新都推进 version**。
- 判定为**可接受**：所有写方都在同一把 `s.mu` 下，flush 用的是「当前内存 version」作 `cur`，必然匹配上一次写 → **不会产生假冲突**；代价仅是无语义的 version 膨胀（版本号不对外做业务判定）。
- 若后续要把 `Version` 暴露给前端做冲突检测，再考虑给 flush 加「无 bump」分支；本批不做。

### 3.3 存量 `version <= 0` 自愈 + 启动回填（对齐 T2.2 §3.2）

- 新增 `normalizeProjectVersion(p)`：`p.Version < 1 → projectVersionFloor`；在 `loadProjects`（`mongo_state.go:571-593`）解码后逐条调用。
- 新增 `backfillProjectVersions()`：`UpdateMany({"version": {"$not": {"$gt": 0}}}, {"$set": {"version": 1}})`；在 `loadMongoState` 中 **`loadProjects()` 之前**调用（对齐 `backfillTaskVersions` 在 `loadTasks` 前的位置）。
  - filter 用 `$not: {$gt: 0}` 而**不是** `$exists: false`：覆盖「缺失 / 显式 0 / null / 负数」以及**滚动发布期间由旧镜像（无 Version 字段）新建**的文档 —— 这类文档对当前进程会永久锁死。
  - 幂等；失败只 `s.log.Warn` 不阻断启动。
- 新增 `healZeroVersionProjectLocked(project, cur)`：filter 未命中时，读库内 version；`> 0` → 如实 `PROJECT_VERSION_CONFLICT`；`<= 0`（存量非法）→ 先 `$set {version: cur}` 再重试一次。**唯一放宽的是明确非法的历史取值，不改变并发语义。**

### 3.4 零副作用提交包装器

新增 `mutateProjectUnsafe(projectID string, fn func(*model.Project) *transport.AppError) *transport.AppError`（`store.go`，对齐 `mutateTaskUnsafe` `store.go:495`）：

```
p, ok := s.projects[projectID]; if !ok { return transport.NotFound(...) }
snapshot := copyProject(p)
if appErr := fn(p); appErr != nil { s.projects[projectID] = snapshot; return appErr }
if appErr := s.persistProjectUnsafe(p); appErr != nil { s.projects[projectID] = snapshot; return appErr }
return nil
```

**创建路径单独处理（修 §2.3 的幽灵项目）**：
`CreateProject` 改为「先在内存建对象 → 调 `persistProjectUnsafe` → **失败则 `delete(s.projects, project.ID)` 再返回**」，与 T2.2 的 `CreateTaskByUser` 完全同款（**不能**用 `mutateProjectUnsafe`，因为进入时对象尚不在 map 中）。

**`ArchiveProject` 的跨聚合顺序**：它先 `resetArchivedProjectTasksUnsafe`（改**任务**并逐条 persist）→ 再 `persistProjectUnsafe(p)` → 再对受影响 agent 逐个 `persistAgentGraphUnsafe`。本批保持现有顺序（任务先落库），只为**项目自身那一步**加版本化 + 失败回滚；**不引入跨聚合事务**（超出本批范围，与 T2.1/T2.2 的取向一致）。

### 3.5 双写过渡与校验（对齐 T2.2 §3.4）

新增只读 `VerifyProjectConsistency() (checked, mismatched int, err error)`：RLock 下取内存快照，逐条 `FindOne` 比对。**只比稳定字段**：

```
Status / Version / Name / PMAgentID / len(Workflows)
```

- **不比 `TaskSummary`**：库内恒为零值（§2.1），比了必然全量假 mismatch。
- **不比 `UpdatedAt`**：BSON Date 只有毫秒精度、内存 `time.Now()` 带纳秒，`Equal` 恒判不等（T2.2 `taskSnapshotMatches` 已有同款结论）。
- **不比 `PMAgent`**（内嵌摘要）：与 `PMAgentID` 冗余且可能因 agent 改名而短暂不一致；只比 ID 足够。
- Mongo 未启用 → 返回 `(0, 0, nil)`。

## 5. 验收标准

1. **Mongo 失败零副作用**（核心路径）：注入 persist 失败 → 接口返错，且 `s.projects[projectID]` **未被修改**。
2. **创建不留幽灵**（修 §2.3）：`CreateProject` 在 persist 失败后 `s.projects` 中**不存在**该 ID。
3. **乐观锁**：并发两次更新同一项目 → 第二次返回 `PROJECT_VERSION_CONFLICT`（409）而非静默覆盖。
4. **重启零丢失**：创建 / 更新（含工作流）/ 归档后 rehydrate → 项目、`Workflows`、`PrimaryWorkflow*`、`Status` 全部可读回。
5. **校验**：双写过渡期 `VerifyProjectConsistency` 的 `mismatched == 0`。
6. **存量兼容**：`version <= 0` 的存量项目被 backfill 修复，不再永久锁死。
7. `gofmt -l` 归零 + `go build ./...` + `go test ./...` + `go test -race ./internal/store/...` 全绿；`store_project_test.go` / `store_workflow_template_test.go` / `store_org_test.go` 不回归。

## 6. 风险与回滚

| 风险 | 缓解 |
|------|------|
| 持锁内做 Mongo I/O 拉长临界区 | 本批先接受（同 T2.1/T2.2）；**T2.5** 再拆细粒度锁；关注 `MONGO_TIMEOUT=5s` |
